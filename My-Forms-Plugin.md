## 1. Что делает плагин

**My Forms Plugin (MFP)** — конструктор форм и менеджер заявок для WordPress. Позволяет создавать любые формы (обратная связь, заявка на обучение, анкеты), собирать ответы в БД, просматривать и фильтровать их в админке и на сайте, выгружать в CSV/Excel.

### Возможности

- **Конструктор форм** — визуальный редактор полей в админке.
- **11 типов полей** — текст, email, число, дата, textarea, select, radio, checkbox-группа, каскадные чекбоксы с суммой, чекбокс-согласие, загрузка файла.
- **Управление программами обучения** — отдельный раздел, с группировкой по категориям, фильтрацией, сортировкой и пагинацией.
- **Интеграция программ в форму** — select/radio/checkbox могут подтягивать программы из БД (с группами).
- **Каскадные чекбоксы** — иерархия «группа → варианты» с автоматическим подсчётом суммы (например, часов обучения).
- **hCaptcha** — защита от спама.
- **Email-уведомления** — на любое количество адресов, свой шаблон письма.
- **Заявки в админке** — таблица со всеми отправками, фильтры, поиск, сортировка, пагинация, массовые действия.
- **Заявки на сайте** — шорткод для вывода таблицы на публичной странице (для определённых ролей).
- **Экспорт** в CSV и Excel.
- **Всплывающая форма** — по клику на кнопку или по URL (`?open_form=1`, `#mfp-popup-1`).
- **Select2** — поиск по программам в выпадающих списках.
- **colResizable** — перетаскивание ширины колонок в таблице заявок с сохранением в localStorage.

## 3. Установка и активация

### 3.1. Установка

**Вариант А — через админку:**

1. Скачать ZIP.
2. **Плагины → Добавить новый → Загрузить плагин** → **Установить** → **Активировать**.

**Вариант Б — через FTP:**

1. Распаковать в `/wp-content/plugins/my-forms-plugin/`.
2. Админка → **Плагины** → **«My Forms Plugin»** → **Активировать**.

### 3.2. Что происходит при активации

Создаются 4 таблицы в БД:

| Таблица | Что хранит |
|---|---|
| `wp_mfp_forms` | Формы (title, fields JSON, settings JSON) |
| `wp_mfp_submissions` | Заявки (form_id, data JSON, ip, is_active) |
| `wp_mfp_programs` | Программы обучения (name, code, duration, group_id, sort_order, is_active) |
| `wp_mfp_program_groups` | Группы программ (name, sort_order) |

Добавляются 7 групп программ по умолчанию:

- образовательная программа повышения квалификации руководящих работников и специалистов
- образовательная программа повышения квалификации рабочих (служащих)
- образовательная программа переподготовки рабочих (служащих)
- образовательная программа подготовки рабочих (служащих)
- образовательная программа переподготовки руководящих работников и специалистов, имеющих высшее образование
- образовательная программа курсы целевого назначения специалистов
- образовательная программа курсы целевого назначения рабочих

Создаются настройки по умолчанию (`mfp_settings`): admin_email, hCaptcha-ключи (пустые), `per_page = 20`.

### 3.3. Пункты меню в админке

После активации появятся два новых раздела:

- **Мои формы** (главное меню) — с подпунктами «Добавить новую», «Заявки», «Настройки».
- **Программы обучения** (отдельное меню).

## 4. Структура плагина и БД

```
my-forms-plugin/
└── my-forms-plugin.php   # единственный файл (все функции, классы, JS, CSS)
```

### 4.1. Схема БД

**`wp_mfp_forms`**
```sql
id           INT UNSIGNED PK AUTO_INCREMENT
title        VARCHAR(255) NOT NULL
fields       LONGTEXT NOT NULL       -- JSON-массив полей
settings     LONGTEXT                -- JSON-настройки (emails, subject, captcha)
created_at   DATETIME
```

**`wp_mfp_submissions`**
```sql
id           INT UNSIGNED PK AUTO_INCREMENT
form_id      INT UNSIGNED NOT NULL    -- ID формы
data         LONGTEXT NOT NULL        -- JSON-объект с ответами
ip           VARCHAR(45)
user_agent   TEXT
created_at   DATETIME
is_active    TINYINT(1) DEFAULT 1     -- 1=активна, 0=удалена
```

**`wp_mfp_programs`**
```sql
id           INT UNSIGNED PK AUTO_INCREMENT
name         VARCHAR(255) NOT NULL
code         VARCHAR(100) NOT NULL UNIQUE
duration     INT UNSIGNED DEFAULT 0    -- часы
group_id     INT UNSIGNED DEFAULT 0
sort_order   INT DEFAULT 0
is_active    TINYINT(1) DEFAULT 1
```

**`wp_mfp_program_groups`**
```sql
id           INT UNSIGNED PK AUTO_INCREMENT
name         VARCHAR(255) NOT NULL
sort_order   INT DEFAULT 0
```

### 4.2. Сериализация полей формы

Поле формы в JSON — объект с ключами:

```json
{
    "type": "select",
    "label": "Выберите программу",
    "name": "program",
    "required": 1,
    "source": "programs",
    "options": [],
    "groups": [1, 2, 3],
    "nested_groups": [],
    "file_settings": [],
    "show_total": 0,
    "placeholder": "",
    "description": "Подсказка под полем",
    "min_date": "",
    "max_date": ""
}
```

## 5. Программы обучения (CPT)

### 5.1. Где управлять

**Админка → Программы обучения**.

### 5.2. Структура страницы

Страница состоит из трёх блоков:

1. **Форма добавления** — вверху.
2. **Фильтры + поиск** — по центру.
3. **Таблица программ** — с сортировкой по колонкам, пагинацией.
4. **Форма редактирования** — появляется внизу при клике на «Редактировать».

### 5.3. Поля программы

| Поле | Обязательное | Описание |
|---|---|---|
| **Название** | ✅ | Полное название программы |
| **Код** | ✅ | Уникальный код (например `ПП-01`) |
| **Длительность (часов)** | — | Число часов |
| **Группа** | — | Из списка групп |
| **Порядок сортировки** | — | Меньше = выше |
| **Активна** | — | Чекбокс (по умолчанию включён) |

### 5.4. Работа со списком

- **Поиск** — по названию или коду (LIKE `%…%`).
- **Фильтр по группе** — выпадающий список.
- **Фильтр по статусу** — все / активные / неактивные.
- **Сортировка** — по ID, названию, коду, часам, группе, порядку, статусу.
- **Пагинация** — количество записей задаётся в настройках (по умолчанию 20).
- **Действия** — Редактировать / Удалить (с подтверждением).

### 5.5. Группы программ

Хранятся в отдельной таблице, по умолчанию 7 групп (создаются при активации). **Управления группами из админки нет** — только через БД. Если нужно добавить/переименовать/удалить группу:

```sql
INSERT INTO wp_mfp_program_groups (name, sort_order) VALUES ('Новая группа', 8);
UPDATE wp_mfp_program_groups SET name = 'Новое название' WHERE id = 1;
DELETE FROM wp_mfp_program_groups WHERE id = 7;
```

Или через фильтр/хук в своём плагине:

```php
add_action('admin_menu', function () {
    add_submenu_page('mfp-forms', 'Группы программ', 'Группы программ', 'manage_options', 'mfp-groups', 'my_groups_admin_page');
});
```

## 6. Формы

### 6.1. Где управлять

**Админка → Мои формы**.

Главная страница — список всех форм: ID, название, дата создания, кнопки «Редактировать» / «Удалить».

### 6.2. Создание формы

**Мои формы → Добавить новую**.

Поля редактора:

| Поле | Описание |
|---|---|
| **Название** | Внутреннее имя формы (видно в админке и в уведомлениях) |
| **Поля** | Конструктор (см. ниже) |
| **Email для уведомлений** | Список через запятую. Если пусто — используется email из настроек |
| **Тема письма** | Если пусто — «Новая отправка формы #ID» |
| **Отправлять уведомление** | Чекбокс (по умолчанию включён) |
| **Включить капчу** | Чекбокс для конкретной формы |

### 6.3. Конструктор полей

Каждое поле — строка с набором параметров:

| Параметр | Описание |
|---|---|
| **Тип** | text / email / number / date / textarea / select / radio / checkbox_group / checkbox_nested / checkbox / file |
| **Метка (label)** | То, что видит пользователь |
| **Имя (slug)** | Уникальный идентификатор, только латиница, цифры, `-`, `_` |
| **Описание / подсказка** | Текст под полем (необязательно) |
| **Источник** | Только для select / radio / checkbox_group: `manual` (вручную) или `programs` (из таблицы программ) |
| **Опции** | Если `manual` — список через запятую |
| **Группы программ** | Если `programs` — чекбоксы групп, из которых подтягивать программы |
| **Показывать сумму** | Только для checkbox_nested |
| **Вложенные группы** | Только для checkbox_nested (см. раздел 15) |
| **Допустимые типы файлов** | Только для file, через запятую (`jpg,png,pdf`) |
| **Макс. размер (МБ)** | Только для file |
| **Мин. дата / Макс. дата** | Только для date |
| **Обязательное** | Чекбокс |

### 6.4. Порядок полей

Поля идут в том порядке, в котором они были добавлены в конструктор. Менять порядок после сохранения можно только через JSON в БД (или добавлением нового поля и удалением старого).

### 6.5. Удаление формы

**Мои формы → [форма] → Удалить**. При удалении также **удаляются все заявки** этой формы (`wp_mfp_submissions` с этим `form_id`).

### 6.6. Назначение формы на страницу

Через шорткод `[myform id="X"]` или через всплывающую кнопку `[mfp_popup_button form_id="X"]`.

## 7. Типы полей

### 7.1. text / email / number / textarea

Стандартные текстовые поля. Валидация:
- `email` — проверка `is_email()`.
- `number` — проверка `is_numeric()`.
- `required` — не пусто.

### 7.2. date

- `<input type="date">` — нативный браузерный выбор даты.
- `min_date` / `max_date` — ограничение диапазона (на сервере и в HTML).
- Сохраняется в формате `дд.мм.гггг` (для читаемости в письме и таблице).

### 7.3. select

- **`source = manual`** — варианты из поля «Опции» (через запятую).
- **`source = programs`** — программы из БД (с фильтром по группам).
- С автоматической инициализацией Select2 (поиск по списку), если источник — программы.
- Значение программы в БД сохраняется как объект: `{ id, name, duration, code }`.

### 7.4. radio / checkbox_group

Аналогично select, но в виде радио-кнопок / чекбоксов. Для `checkbox_group` поддерживается выбор нескольких программ.

### 7.5. checkbox

Одиночный чекбокс-согласие. В БД сохраняется как строка `Да` / `Нет`. Обязательность проверяется как «должен быть отмечен».

### 7.6. checkbox_nested

Каскадная структура «группа → варианты» с подсчётом суммы. Подробно — [раздел 15](#15-каскадные-чекбоксы-checkbox_nested).

### 7.7. file

- Загрузка файла через `wp_handle_upload()`.
- Проверка размера (`max_size`) и расширения (`allowed_types`).
- В БД сохраняется объект `{ url, file, name }`.
- Файл физически лежит в `wp-content/uploads/`.
- В админке/на сайте — ссылка на скачивание.

## 8. Заявки

### 8.1. Где смотреть

- **Админка → Мои формы → Заявки** — полный список с расширенными фильтрами.
- **На сайте** — через шорткод `[mfp_submissions_list]` (см. раздел 10).

### 8.2. Таблица заявок в админке

Колонки:

| Колонка | Описание |
|---|---|
| Checkbox | Для массовых действий |
| **ID** | ID заявки |
| **Форма** | К какой форме относится |
| **Поля формы** | По одной колонке на каждое поле (заголовки берутся из label) |
| **Дата** | `created_at` |
| **IP** | IP-адрес пользователя |
| **Статус** | Активна / Неактивна + кнопка «Деактивировать/Активировать» |

### 8.3. Фильтры

- **Форма** — по ID формы (или через субменю «Все формы / Конкретная»).
- **Дата с / по** — `<input type="date">`.
- **Программа** — по ID программы (ищет в JSON-поле).
- **Статус** — все / активные / неактивные.
- **Поиск** — по содержимому `data` (LIKE).

### 8.4. Сортировка

- ID, дата, IP, статус — по клику на заголовок.
- Клик повторно — меняет направление (ASC / DESC).

### 8.5. Массовые действия

Выбрать чекбоксами → внизу **«Массовые действия»**:
- **Удалить выбранные** — ставит `is_active = 0` (не физическое удаление, а «мягкое»).
- **Активировать выбранные** — `is_active = 1`.
- **Деактивировать выбранные** — `is_active = 0`.

### 8.6. Просмотр одной заявки

**Отдельной страницы нет.** Все данные показываются в таблице. Если нужно детально — откройте исходник в БД (`wp_mfp_submissions → data`).

### 8.7. Что удаляется, а что нет

- **Деактивация** (`is_active = 0`) — заявка остаётся в БД, но не показывается в списках.
- **Удаление формы** — удаляются **все** её заявки (безвозвратно).
- **Физическое удаление записи из БД** — возможно только через SQL.

## 10. Шорткоды

### 10.1. `[myform id="X"]`

Выводит форму на странице.

```
[myform id="1"]
```

### 10.2. `[mfp_programs group="X"]`

Выводит список программ в виде таблиц, сгруппированных по группам.

- `group` — ID группы (если `0` — все группы).

```html
[mfp_programs group="1"]
```

Колонки: **Код программы | Наименование | Количество часов**.

### 10.3. `[mfp_submissions_list per_page="20"]`

Выводит таблицу заявок **на публичной странице** (для менеджеров, без захода в админку).

- `per_page` — переопределяет количество записей на странице.

```html
[mfp_submissions_list per_page="50"]
```

Возможности:
- Фильтры (форма, даты, программа).
- Массовые действия (удалить/активировать).
- Экспорт Excel.
- Пагинация.
- Select2 для фильтра программ.
- colResizable для изменения ширины колонок.

**По умолчанию шорткод доступен всем.** Проверка авторизации закомментирована в коде (`//if ( ! is_user_logged_in() )`). Если нужна защита — раскомментируйте эту строку.

### 10.4. `[mfp_popup_button]`

Кнопка, открывающая форму в модальном окне.

```
[mfp_popup_button
    text="Записаться на обучение"
    form_id="1"
    button_class="mfp-popup-button"
    title="Заявка на обучение"
    subtitle="Мы свяжемся с вами в ближайшее время"
]
```

Все атрибуты — необязательные, кроме `form_id`. Стилизация кнопки — через `button_class`.

### 10.5. Автооткрытие формы по URL

- **Через hash:** `https://site.com/page/#mfp-popup-1` — откроет popup формы ID=1.
- **Через query:** `https://site.com/page/?open_form=1` — то же самое.

Это удобно для внешних ссылок и рекламы.

## 11. hCaptcha

### 11.1. Получение ключей

1. Зарегистрироваться на https://www.hcaptcha.com/.
2. Создать сайт (Site) → получить **Site Key** и **Secret Key**.
3. В настройках плагина (**Мои формы → Настройки**) вставить оба ключа.

### 11.2. Как работает

- Если в настройках задан `Secret Key` и в форме включён чекбокс «Включить капчу» — при отправке виджет рендерится в форме.
- При сабмите сервер проверяет `h-captcha-response` через `https://api.hcaptcha.com/siteverify`.
- Если проверка не прошла — форма возвращает ошибку.

### 11.3. Отключение

- Убрать `Secret Key` из настроек — капча перестаёт работать на всех формах.
- Или снять чекбокс «Включить капчу» у конкретной формы.

## 12. Email-уведомления

### 12.1. Как настроить

В редакторе формы:
- **Email для уведомлений** — список через запятую (`admin@site.ru, manager@site.ru`).
- **Тема письма** — свой текст, если пусто — `Новая отправка формы #ID`.
- **Отправлять уведомление** — чекбокс.

### 12.2. Что в письме

```
Новая отправка формы: <название формы>

<Метка поля 1>: <значение>
<Метка поля 2>: <значение>
...

Дата: <Y-m-d H:i:s>
```

- Для `checkbox_nested` — список выбранных вариантов + `(Сумма: N)`.
- Для `programs` — `Код - Название (N ч.)`.
- Для `file` — `Имя файла (URL)`.

### 12.3. Отправка

- Используется `wp_mail()`.
- Адрес отправителя = стандартный (`wordpress@ваш-домен`).
- Если нужно изменить — через фильтр `wp_mail_from` / `wp_mail_from_name` в `functions.php` темы или через SMTP-плагин.

### 12.4. Что делать, если письма не приходят

- Проверить `wp_mail()` через плагин **Check Email** или **WP Mail SMTP**.
- Хостинг может блокировать отправку через `mail()`. Решение — SMTP-плагин (WP Mail SMTP / Post SMTP).
- Проверить папку «Спам» у получателя.
- Убедиться, что в поле «Email для уведомлений» нет опечаток.

## 13. Экспорт CSV / Excel

### 13.1. Где кнопки

- **В админке** — **Мои формы → Заявки** → вверху кнопки «Экспорт CSV» / «Экспорт Excel».
- **На сайте** — шорткод `[mfp_submissions_list]` → кнопка «Экспорт Excel».
- В шорткоде `mfp_submissions_list` CSV **не показывается** обычным пользователям (только в админке).

### 13.2. Что экспортируется

- **Все** заявки, подходящие под текущие фильтры (форма, даты, программа).
- Все поля формы (колонки — по label).
- Колонка «Дата».

### 13.3. Формат

- **CSV** — UTF-8 с BOM (`\xEF\xBB\xBF`), чтобы Excel не ломал кириллицу.
- **Excel** — HTML-таблица с `Content-Type: application/vnd.ms-excel` (открывается в Excel, но это не настоящий XLSX).

### 13.4. Что делать, если Excel открывает кириллицу «крякозябрами»

- Использовать **CSV с BOM** — уже реализовано.
- Или в Excel: **Данные → Из текста/CSV** → указать кодировку UTF-8.

### 14.1. Что даёт

## 15. Каскадные чекбоксы (checkbox_nested)

### 15.1. Что это

Поле типа «группа чекбоксов с иерархией»: внутри **групп** — **варианты**, у каждого варианта — числовое значение (например, часы обучения). При выборе вариантов сумма считается автоматически.

Пример использования: «Выберите курсы для повышения квалификации», где под каждым направлением — список курсов с часами.

### 15.2. Настройка в админке

1. Добавить поле → тип **«Чекбоксы с группами (сумма)»**.
2. В блоке «Показывать сумму значений» — поставить галочку (если нужно).
3. Нажать **«Добавить группу»** — появится блок группы.
4. Ввести название группы.
5. Нажать **«Добавить вариант»** внутри группы — появятся поля:
   - **Название варианта** (label).
   - **Значение** (число, например часы).
6. Повторить для всех групп и вариантов.

### 15.3. Как работает на фронтенде

- Чекбокс у группы **автоматически отмечается**, когда выбраны все её варианты.
- При клике на группу — отмечаются/снимаются все её варианты.
- Если указано «Показывать сумму» — под списком отображается **«Суммарное количество часов: N»**.
- Сумма пересчитывается через jQuery при каждом изменении.

### 15.4. Как сохраняется в БД

JSON вида:

```json
{
    "values": {
        "0": { "0": "16", "1": "32" },
        "1": { "0": "8" }
    },
    "sum": 56,
    "selected_labels": [
        "Курс А (16 ч.)",
        "Курс Б (32 ч.)",
        "Курс В (8 ч.)"
    ]
}
```

В письме и таблице выводится как `Курс А, Курс Б, Курс В (Сумма: 56)`.

### 15.5. Ограничения

- Вложенность только **два уровня**: группа → вариант.
- Нельзя редактировать структуру после сохранения формы (только через JSON в БД).
- Числа — целые или дробные (`parseFloat`).

## 16. Загрузка файлов

### 16.1. Настройка поля

Тип поля — **file**. Параметры:

- **Допустимые типы** — расширения через запятую (`jpg,png,pdf,docx`).
- **Макс. размер (МБ)** — целое число (по умолчанию 5).

### 16.2. Как работает

1. Пользователь выбирает файл в форме.
2. При отправке — `wp_handle_upload()` (стандартная функция WP).
3. Проверка размера и расширения до `wp_handle_upload`.
4. Файл кладётся в `wp-content/uploads/YYYY/MM/`.
5. В БД сохраняется объект: `{ url, file, name }`.
6. В админке / на сайте — ссылка для скачивания.

### 16.3. Ограничения

- **Не проверяется MIME-тип** — только расширение. Если нужна строгая проверка — добавьте в обработчик `mfp_handle_submit()` проверку `wp_check_filetype_and_ext()`.
- **Файлы не удаляются** при удалении заявки (лежат в `uploads/`). Чистить вручную.
- **Размер** ограничен также `upload_max_filesize` и `post_max_size` в `php.ini`.

## 18. Миграция dev → production

### 18.1. Перенос плагина

Скопировать папку `my-forms-plugin/` в `/wp-content/plugins/` на production. Активировать.

### 18.2. Перенос БД

Плагин хранит данные в 4 таблицах:

- `wp_mfp_forms`
- `wp_mfp_submissions`
- `wp_mfp_programs`
- `wp_mfp_program_groups`

**Вариант А — полный дамп:**

```bash
mysqldump -u devuser -p devdb wp_mfp_forms wp_mfp_submissions wp_mfp_programs wp_mfp_program_groups > mfp_export.sql
# На prod
mysql -u produser -p proddb < mfp_export.sql
```

⚠️ **Не забудьте про `wp_options`:** настройки `mfp_settings` лежат там. Если переносите частично — добавьте:

```sql
SELECT * FROM wp_options WHERE option_name = 'mfp_settings';
```

И перенесите вручную или через:

```bash
wp option get mfp_settings --format=json > mfp_settings.json
wp option update mfp_settings "$(cat mfp_settings.json)" --format=json
```

**Вариант Б — полный перенос сайта** (рекомендуется): переносится БД целиком + `wp-content/`.

### 18.3. Файлы, загруженные через формы

Лежат в `wp-content/uploads/YYYY/MM/`. Переносятся вместе с остальными uploads:

```bash
rsync -av /path/dev/wp-content/uploads/ /path/prod/wp-content/uploads/
```

### 18.4. Что проверить после переноса

- [ ] Меню «Мои формы» и «Программы обучения» есть в админке.
- [ ] Таблицы в БД созданы (`wp_mfp_*`).
- [ ] Формы открываются, поля отображаются.
- [ ] Программы видны в списке.
- [ ] Заявки отображаются.
- [ ] Тестовая отправка формы проходит.
- [ ] Письмо приходит на email.
- [ ] hCaptcha работает (если настроена).

### 18.5. Смена домена

Плагин **не хранит** абсолютных URL в БД (только в загруженных файлах — там полные URL). Если домен меняется:

```bash
wp search-replace 'dev.gazinstitut.by' 'gazinstitut.by' wp_mfp_submissions --include-columns=data --precise
```

Или через Better Search Replace.

### 18.6. Cron и фоновые задачи

Плагин **не использует** WP-Cron. Всё выполняется по запросу пользователя.

## 20. Диагностика проблем

### 20.1. Пункта «Мои формы» нет в админке

- Плагин активен? **Плагины → Установленные**.
- Проверить `wp-content/debug.log` на фатальные ошибки.
- Проверить, что пользователь — администратор (`manage_options`).

### 20.2. Форма не отправляется

- **F12 → Console** — есть ошибки JS?
- **F12 → Network → submit** — какой ответ сервера?
- Если белый экран — ошибка PHP. Включить `WP_DEBUG_LOG` и смотреть `debug.log`.
- Если редирект на `wp_die` — там будет текст ошибки (валидация).
- Если форма с файлом — проверить `upload_max_filesize`.

### 20.3. Письма не приходят

- Проверить `wp_mail()` через **Check Email** плагин.
- Установить **WP Mail SMTP** и настроить SMTP.
- Проверить папку «Спам».
- Проверить, что `Email для уведомлений` валидный.

### 20.4. hCaptcha не отображается

- **F12 → Network** — грузится ли `https://js.hcaptcha.com/1/api.js`?
- Если нет — блокировка CDN, использовать прокси.
- Если виджет есть, но не рендерится — **F12 → Console**, проверить ошибки.
- Убедиться, что `Site Key` заполнен в настройках.

### 20.5. Select2 не работает

- **F12 → Console** — `$.fn.select2 is not defined`?
- Проверить `wp_footer`, что `select2-css` и `select2-js` подключились (`F12 → Network`).
- Если CDN недоступен — заменить на локальную копию (раздел 14.3).

### 20.6. Экспорт CSV — кириллица не читается в Excel

- CSV **уже** с BOM (`\xEF\xBB\xBF`) — должен открываться корректно.
- Если нет — Excel мог проигнорировать BOM. Открыть через **Данные → Из текста/CSV** → UTF-8.
- Или использовать **Экспорт Excel** (HTML-таблица).

### 20.7. Программы не отображаются в форме

- Проверить, что в программе `is_active = 1`.
- Проверить, что группа программы выбрана в настройках поля.
- Проверить, что в поле `source = programs`.
- Открыть **F12 → Network** → нет ли ошибки 500.

### 20.8. Каскадные чекбоксы не считают сумму

- **F12 → Console** — ошибки?
- Проверить, что в форме есть поле `checkbox_nested` с включённым «Показывать сумму».
- Проверить, что у всех вариантов заполнено «Значение» (число).
- Проверить, что на фронтенде загружается скрипт `mfp_nested_checkboxes_js()` (`F12 → Elements → скрипт`).

### 20.9. Popup не открывается

- **F12 → Console** — ошибка `mfpOpenPopup is not defined`?
- Проверить, что кнопка `[mfp_popup_button]` есть на странице.
- Проверить, что скрипт `mfp_popup_scripts()` подключён (`F12 → Network → inline script`).
- Если URL `?open_form=1` — проверить, что форма с этим ID существует и есть popup-кнопка на странице.

### 20.10. Заявки не отображаются на сайте через шорткод

- **Мои формы → Настройки** — проверить `per_page`.
- **F12 → Network** — запрос шорткода отработал?
- Проверить, что заявки `is_active = 1`.
- Проверить фильтры в URL (`?form_id=`, `?date_from=` — могут отсекать всё).

### 20.11. При активации плагина ошибка `Table already exists`

- Не критично — `CREATE TABLE IF NOT EXISTS` игнорирует.
- Если ошибка про `dbDelta` — проверить права БД (нужны `CREATE`, `ALTER`).

### 20.12. При сохранении формы теряются поля

- **F12 → Network → submit** — какие данные ушли.
- Проверить `post_max_size` (если полей много — превышение лимита).
- Проверить `max_input_vars` (по умолчанию 1000, может быть мало при >50 полях).

## 21. Хуки и кастомизация

В плагине **нет** собственных фильтров/действий. Кастомизация — через стандартные хуки WordPress + прямой код.

### 21.1. Изменить шаблон письма

Перехватить `wp_mail` через фильтр:

```php
add_filter('wp_mail', function ($args) {
    // Условие: письмо от MFP
    if (strpos($args['subject'], 'Новая отправка формы') !== false) {
        $args['message'] = "Своё сообщение\n" . $args['message'];
    }
    return $args;
});
```

Или переопределить `mfp_handle_submit()` полностью в своём плагине (удалить хук и добавить свой).

### 21.2. Изменить экспорт

Переопределить `mfp_export_submissions()` через `remove_action` + свой вариант.

### 21.3. Добавить своё поле

Добавить пункт в массив `$allowed_types` в `mfp_sanitize_fields()` и обработку в `mfp_shortcode()` / `mfp_handle_submit()`.

### 21.4. Защитить шорткод `[mfp_submissions_list]` по роли

В коде шорткода есть закомментированная проверка `is_user_logged_in()`. Раскомментировать:

```php
if ( ! is_user_logged_in() ) {
    return '<p>Для просмотра заявок необходимо <a href="' . wp_login_url( get_permalink() ) . '">войти</a>.</p>';
}
```

Или по роли:

```php
if ( ! current_user_can('manage_options') ) {
    return '<p>Доступ запрещён.</p>';
}
```

### 21.5. REST API

Плагин **не предоставляет** REST-эндпоинтов. Если нужно — добавить через `register_rest_route()` в своём плагине.

### 21.6. Webhook при новой заявке

```php
add_action('init', function () {
    // В mfp_handle_submit() после wp_mail() нет хука — можно добавить свой
    // через переопределение функции или через фильтр 'wp_mail'
});
```

Проще всего — переопределить `wp_handle_upload` + `wp_mail` или добавить свой код в `mfp_handle_submit()`.

## 22. Безопасность

### 22.1. SQL-инъекции

Все запросы используют `$wpdb->prepare()` или `$wpdb->insert()` / `$wpdb->update()` с форматами. **Прямых конкатенаций пользовательского ввода нет** — это правильно.

### 22.2. XSS

Все выводы экранируются `esc_html()` / `esc_attr()` / `esc_url()`. Есть исключения:

- `mfp_show_success()` — выводит простой HTML, но только при `$_GET['mfp_success'] == '1'`.
- Описания полей — выводятся через `wp_kses_post()`.

### 22.3. CSRF

- Формы в админке — `wp_nonce_field()`.
- Публичные формы — `wp_nonce_field('mfp_submit', 'mfp_nonce')` + проверка при отправке.
- AJAX — `check_ajax_referer()`.

### 22.4. Загрузка файлов

- Проверка расширения (`allowed_types`) и размера (`max_size`).
- `wp_handle_upload()` — стандартная, безопасная.
- **Не проверяется MIME** — если нужно, добавьте:

```php
$check = wp_check_filetype_and_ext($tmp_name, $file_name);
if (!$check['type']) {
    $errors[] = 'Недопустимый тип файла.';
}
```

### 22.5. hCaptcha

Если капча включена, но `Secret Key` пустой — проверка **не выполняется**. Это значит: пользователь может отправлять форму без капчи (но капча и не показывается). Убедитесь, что оба ключа заполнены, если хотите защиту.

### 22.6. Права доступа

- Все админ-страницы — `manage_options` (только администраторы).
- Шорткод `[mfp_submissions_list]` — **по умолчанию без защиты** (см. 21.4).
- `wp_ajax_mfp_toggle_status` — `current_user_can('manage_options')`.
